```markdown
## 1. 신규 스레드 착수 프로토콜

> **[고정 프롬프트] 매 스레드 시작 시 아래 한 줄을 복사하여 주입하세요:**
> 이번 스레드에서는 `[경로]/[기능명]_SPEC_BACKLOG.md` 파일의 '예정사항' 최상단(첫 번째) 항목을 파악하여 수행하세요. 항목과 연계된 스펙 절을 숙지한 뒤 작업을 진행하고, 결과물 검증 후 사용자가 승인하면 백로그 문서를 완료 상태로 갱신하고 스레드를 종료하세요.

### 스레드 실행 순서
1. **읽기**: 백로그와 연계 스펙의 해당 절 번호를 확인한다.
2. **진행 상태 점검**: `진행 중`이 `(없음)`인지 확인한다. 기존 항목이 남아있다면 이어받기 전에 `git status`/`git diff`로 워킹 트리를 먼저 점검한다 — 지난 스레드가 중단됐다는 신호일 수 있다.
3. **작업 및 질의**: 지정된 스펙 범위만 작업한다. `착수 전 확인:` 질문이 있다면 사용자에게 확인 후 진행한다. 범위를 넘거나 다음 항목을 먼저 손대지 않는다.
4. **결정 역류**: 중요한 아키텍처 판단 및 버린 대안은 스펙 문서에 `> 구현 결정(#N):` 각주로 기록한다(작성 규칙은 `_SPEC_PLAN.md` 참고).
5. **완료 갱신**: 사용자 승인 후에만 일감을 [완료 사항]으로 옮기고 아래 필드를 채운다.
6. **다음 안내**: 다음 예정 항목 번호만 간략히 브리핑하고 마친다.

## 2. 일감 관리

번호는 전체를 통틀어 하나의 연속된 시퀀스입니다. **실행 순서는 예정사항 목록에 적힌 줄 위치 그 자체**입니다 — 우선순위가 바뀌면 항목을 위아래로 옮기고, 별도로 "지금 순서는 이렇다"는 문장을 적지 않습니다.

### 진행 중

(없음)

### 예정사항

1. <제목> (AI 모델: <Sonnet/Opus/...>, 노력정도: <낮음|중간|높음|최대>)
   - 참고: <스펙 절 번호>
   - 선행 조건: <있으면>
   - 착수 전 확인(사용자): <AI가 대신 정하면 안 되는 것>

### 완료 사항

0. <제목> (AI 모델: ..., 노력정도: <예상> → 실제: <실측>) [완료]
   - 참고: <스펙 절 번호>
   - 산출물: <실제로 바뀐 파일, 목록>
   - 구현 결정: <스펙 각주 위치, 또는 "해당 없음">
   - 비고: <작업 중 알아낸 것 / 다음 항목에 넘기는 메모 — 자유 텍스트>
   - 커밋: `<커밋 메시지>`
   - 승인 완료: YYYY-MM-DD
```

**왜 진행중 → 예정사항 → 완료 사항 순서인가**: 완료 항목은 트랙이 진행될수록 계속 쌓입니다. 지금 실행 가능한 부분(진행중·예정사항)을 먼저 두면, 새 스레드가 문서를 열 때마다 쌓인 완료 이력을 지나칠 필요 없이 바로 할 일을 봅니다.

## 3. 서두에 넣지 않는 것

의존관계·선행조건·미확정 목록은 여기 요약하지 않고 각 항목의 `선행 조건`/`착수 전 확인` 필드에만 적습니다. 두 군데에 적으면 한쪽이 낡습니다 — 서두에는 스코프(이 트랙이 다루는 것/안 다루는 것)만 최소로 남기세요.
