> **이 문서는 읽는 문서가 아니라 찾는 문서다.**
> 활성 백로그(`work/roadmap/260923-_ACTIVE_BACKLOG.md`)의 **함정 색인**에서 지금 하는 일에 걸리는
> 키워드를 먼저 고르고, **그 번호만** 여기서 편다. 84건을 처음부터 읽지 않는다.

**무엇인가** — 이 저장소가 **실제로 한 번씩 밟은 것**들이다. 지어낸 주의사항이 아니라, 대부분
버그로 한 번 겪고 고친 뒤 *"다음 사람이 또 밟겠다"* 싶어 적어 둔 것이다. 그래서 문장이
*"~하지 말 것"* 보다 *"~했더니 ~가 됐다"* 쪽이 많다.

## ⚠️ 읽는 사람이 알아야 할 것 넷

1. **번호는 영구불변이다.** 죽은 함정도 번호를 재사용하지 않는다 — 옛 문서의 「함정 44」가
   다른 것을 가리키게 되는 순간 **그 문서가 전부 거짓이 된다.**
2. **색인과 여기가 어긋나면 색인이 옳다.** 색인은 계속 고쳐 왔고, 여기 전문은 각 세대가 쓴
   시점에 **동결**됐다. 뒤집힌 것에는 색인 쪽에 ⚠️가 붙어 있다(예: 함정 37 백업은 2026-09-22에
   뒤집혔다 — 이제 백업이 **된다**).
3. **날짜와 `#번호`가 함께 적혀 있다.** 그 번호로 `git log --grep "backlog #NNN"`을 치면
   **그때 무엇을 고쳤는지**가 나온다. 전문보다 그쪽이 정본이다.
4. **고치지 않는다.** 새로 알게 된 것은 **색인에 ⚠️로 적고**, 새 함정이면 다음 번호를 딴다.
   여기를 고치기 시작하면 「동결」이라는 말이 뜻을 잃는다.

## 이 문서가 생긴 이유 (2026-09-23, 백로그 #194)

전문이 **봉인 백로그 넷에 흩어져 있었다** — 각 세대가 새 함정을 자기 파일에 전문으로 쓰고,
봉인할 때 색인만 다음 세대로 넘기는 관행 때문이다. 세대가 쌓이면서 포인터가 넷이 됐고,
**그래서 봉인 문서를 지울 수 없었다**(지우면 색인이 허공을 가리킨다).

여기로 모으면서 **원본은 그대로 뒀다** — 봉인 문서는 고치지 않는 것이 그 문서들의 규칙이다.

33. **⚠️ 16KB 페이지 대응은 축이 둘이다 — 하나만 해 놓고 됐다고 하지 말 것** (2026-09-06, #118)

      **zip 정렬까지 16KB**여야 한다. 즉 끄는 순간 요구 조건이 하나 늘어난다.
    - ⚠️ **ⓑ만으로는 통과하지 못한다 — 811이 그 증거다.** 이 저장소는 ⓑ가 **이미 켜져 있었는데도**
      반려됐다. ⓑ는 **남이 만든 `.so`를 못 고칠 때의 우회로**이지 ⓐ의 대체재가 아니다.
    - ✅ **다른 앱에서 교차 확인했다.** 같은 사용자의 장기 앱(`/Users/ryan9kim/worksoc/jg-v2.0`)이
      같은 오류로 고생하며 **자기 엔진은 ⓐ로**(`-Wl,-z,max-page-size=16384`, `CMakeLists.txt`의
      `target_link_options`), **고칠 수 없는 RN 프리빌트 라이브러리**(`libyoga.so`·`libhermes.so`)는
      **ⓑ로** 넘겼다 — 그 기록이 **이 저장소 밖**의
      `/Users/ryan9kim/worksoc/jg-v2.0/main/docs/16kb-native-lib-troubleshooting.md`에 있다.
      **우리는 4KB였던 것이 우리가 빌드하는 하나뿐이라 ⓐ만으로 끝났다.**
    - **확인하는 법**: 번들에서 `base/lib/**/*.so`를 꺼내 ELF **프로그램 헤더**의 `PT_LOAD`에서
      `p_align`을 읽는다. ⚠️ `file`·`readelf -h`로는 안 보인다 — 헤더 요약이 아니라 프로그램 헤더다.

46. **⚠️ `rememberUpdatedState`는 구조적 동등성이다 — 지역 함수 참조(`::f`)는 새 클로저여도 `==`라 갱신이 걸러진다** (2026-09-11, #140)
    - `rememberUpdatedState(x)` = `mutableStateOf`(**구조적** 동등성)에 매번 `x`를 넣는 것. 같은 지역 함수의 참조는 컴포지션마다
      **다른 값을 쥔 새 클로저**인데도 서로 `==`라서 새것이 **걸러지고 옛것이 남는다.** 오래 사는 코루틴(`pointerInput(Unit)`,
      `LaunchedEffect(Unit)`)이 그 상태로 콜백을 부르면 **첫 컴포지션의 콜백**이 계속 불린다.
    - 실측: 코치마크 흡수 층이 첫 단계의 `ack`만 불러 둘째부터 넘어가지 않았다. `알겠어요`(`clickable`)는 멀쩡했다 —
      `clickable`은 `onClick`을 **참조로** 비교해 매번 새것을 받는다. 그래서 "버튼은 되는데 층만 안 된다"로 보였다.
    - 처방: 콜백을 들 때는 `remember { mutableStateOf(cb, referentialEqualityPolicy()) }.apply { value = cb }`. 또는 호출부에서
      지역 함수 참조 대신 람다를 넘긴다(람다는 참조 동등). `FirstDolGuideContractTest.aLocalFunctionReferenceLooksEqualToItsStaleSelf`가
      이 성질을 못박는다 — 코틀린이 바뀌어 빨개지면 우회가 아직 필요한지 다시 볼 것.

80. **⚠️ 공유 작업 트리에서 `git add <경로>` 다음의 `git commit -m`은 남의 스테이징을 삼킨다 — `git commit <경로> -m` 으로 커밋한다** (2026-09-23, refactor backlog #62에서 실제 발생·복구)

    `git add <정확한 경로>`로 자기 파일만 올려도 **안전하지 않다.** 인덱스는 작업 트리 전체가 공유하는
    하나이고, **`add`와 `commit` 사이에 다른 세션이 자기 파일을 스테이징**할 수 있다.
    실제로 일어난 일: 자기 파일 1개를 `add` 한 뒤 `git commit -m` 했더니 다른 세션이 그 사이에 올려 둔
    **무관한 35개 파일(삭제 포함)이 그 커밋에 함께 들어갔다.**
    - **처방**: **경로를 지정해 커밋한다** — `git commit <경로> -m "..."`.
      이 형태는 **지정한 경로의 변경만 커밋하고 인덱스의 나머지는 건드리지 않는다.**
    - **이미 삼켰다면**: `git reset --soft HEAD~1`(HEAD만 되돌리고 인덱스·워킹트리는 그대로 — 비파괴적)
      으로 커밋만 취소한 뒤 경로 지정 커밋으로 다시 낸다. ⛔ `git reset --hard`는 절대 쓰지 마라.
    - ⚠️ **`git status`로 확인해도 소용없다** — 확인 시점과 커밋 시점 사이가 창이다.
      *확인이 아니라 형태*로 막아야 한다.
    - 함정 72(공유 트리에서 대량 개명 금지)와 같은 계보다. 그쪽이 **파일 충돌**이라면 이쪽은 **인덱스 충돌**이다.

      341파일 ±14,232줄이 재작성되고, 자동 수정이 안 되는 위반 249파일이 `spotlessApply` 뒤에도 남는다. 규칙을 더 켤 때는
      `ktlint_standard_<규칙> = enabled`를 한 줄씩.
    - ktlint를 올릴 때는 `*/build/spotless-lints/` 아래가 비었는지 본다 — ktlint 내장 파서(1.8.0은 Kotlin 2.2.21)가 프로젝트
      Kotlin보다 늦으면 새 문법 파일에서 format이 아니라 lint 실패로 빨개진다.
