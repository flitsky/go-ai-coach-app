# 출석 보상 정책

작성일: 2026-08-31 (백로그 #55에서 확정, 사용자 결정)

이 문서는 **"출석 보상을 어떻게 주는가"의 단일 출처**다. 표 자체는 코드
(`shared/.../application/attendance/AttendanceRewardPolicy.kt`)가 실행하고, 여기에는 **그렇게
정한 이유**를 적는다 — 숫자만 코드에 남으면 다음 사람이 "왜 3일차인가"를 알 수 없어 같은 논의를
반복하게 된다.

(이 저장소에서 실제로 있었던 사고다 — `DOCS_INDEX.md`의 2026-08-29 (2) 항목 참고).

## 1. 핵심 정책: 데일리 보상은 **고정 불변의 자동 수령**이다

**출석 보상은 선택이 아니다.** 회차마다 받을 것이 정해져 있고, 조건을 채우면 반드시 지급된다.
사용자가 "받을지 말지"를 고민할 여지를 두지 않는다.

**왜 그렇게 정했는가(2026-08-31 사용자 결정)**: 이 보상 체계의 목적은 *"모으게 하는 것"이 아니라
**제때 쓰게 하는 것**"* 이다. 받는 순간을 사용자가 조절할 수 있게 하면 "아껴 뒀다가 나중에"라는
심리가 생기고, 그건 이 체계가 만들려는 행동(오늘 들어와서 오늘 쓴다)과 정반대다.

### 이 정책에서 따라 나오는 것들

- **팝업에 "나중에" 같은 보류 선택지를 두지 않는다.** 어떤 경로로 팝업을 닫든 지급된다 —
  버튼, 뒤로 가기, 바깥 탭 모두 같다.
  · ⚠️ **버튼만 없애고 뒤로 가기로는 미뤄지게 두면 안 된다.** 그러면 정책은 문서에만 있고
    실제로는 숨은 보류 경로가 남는다. 2026-08-31에 이 함정이 실제로 지적됐다.
- **보유 상한을 둔다**(아래 3장). 자동으로 계속 들어오는데 상한이 없으면 쌓이기만 하고,
  "쓰자"는 유인이 사라진다.
- **밀린 회차는 한 번에 모아 지급한다.** 며칠 못 들어왔다고 보상이 사라지지 않는다 —
  "고정 불변"이라는 말의 다른 쪽 면이다.
- ⚠️ **도장이 찍히는 연출은 이 정책 아래에서 성립하지 않는다**(#57에서 확인). Claim하는 순간
  팝업이 닫히므로 도장이 찍히는 그 순간에 판이 사라진다. 연출을 넣으려면 **"받고도 팝업이
  잠시 남는다"** 는 정책 변경이 먼저다 — 그건 위 "보류 경로를 남기지 않는다"와 정면으로 부딪힌다.

### ⚠️ 뒤집힌 이전 결정

킥오프 플랜 5.1절(2026-08-24)은 *"그냥 닫으면 지급되지 않고 미지급으로 남아 다음 실행에 다시
뜬다"* 로 정해 뒀다. **2026-08-31에 위 정책으로 대체됐다.** 그때는 "화면에 들어오는 것만으로
지급되지 않는다"(사용자가 무엇을 받았는지 보게 한다)가 목적이었는데, 그 목적은 **팝업이 내용을
보여주는 것만으로 이미 달성**되고 보류 선택지까지 필요하지는 않았다.

## 2. 보상표 (2026-08-31 확정)

| 회차 | 보상 |
| --- | --- |
| 1일차 | 형세 보기 1회권 30 |
| 2일차 | 추천 수 1회권 30 |
| 3일차 | **무르기 무제한(영구)** |
| 4일차 | 광고 스킵권 3 |
| 5일차 | 조각 1 (연습생 돌뫼) |
| 6일차 | 조각 1 (사범 묘수) |
| **7일차** | **캐릭터 해금: 도장생 반상** — 소모품 없음 |
| 14·21일차 | 형세 50 · 추천 50 · 스킵 3 |
| **28일차** | **캐릭터 해금: 관장 천원** — 소모품 없음 |
| 35일차 이후 (7의 배수) | 형세 50 · 추천 50 · 스킵 3 |

### 각 배치의 이유

- **형세와 추천 수를 1·2일차로 나눴다** — 한 번에 주면 둘이 뭉뚱그려져 각각이 무엇인지 인지되지
  않는다. 하루씩 떼어 주면 그날 그것만 쓰게 된다.
- **무르기는 3일차다.** ⚠️ **1일차가 아닌 것이 핵심이다.** 무르기는 1회권이 아예 없어서
  (소모품은 형세·추천·스킵 셋뿐) 1·2일차에 쓰려면 광고를 봐야 하고, 광고 스킵권조차 4일차에
  처음 나온다. **이틀 동안 "이건 유료구나"를 겪은 뒤에 받아야** 공짜로 받은 것이 아니라
  값나가는 것을 받은 것이 된다. 앞으로 당기면 그 학습이 통째로 사라진다.
- **5·6일차 조각은 맛보기다** — *"캐릭터는 조각을 모아야 열리고, 조각은 광고를 봐야 쌓인다"*
  를 알려 광고 시청으로 유입시키는 것이 목적이다.
- **7·28일차는 캐릭터라 소모품을 얹지 않는다.** 캐릭터 자체가 그 회차의 보상이다.
- **반복 회차는 갈증이 남게 준다** — 한 주가 풍족하면 프리미엄(구독)의 의미가 옅어진다.

### ⚠️ 조각의 무광고 경로는 **의도적으로 없다**

출석으로 나오는 조각은 5·6일차에 **1개씩이 전부**다. 돌뫼는 5개, 묘수는 10개가 필요하므로
각각 **광고 4번, 광고 9번**이 더 필요하다.

*"반복 회차(35일차~)에 조각을 1개씩 얹어 느린 무광고 경로를 두자"* 는 제안은 **2026-08-31에
기각됐다** — 그 시점이면 광고로 이미 확보한 사용자가 대부분이고, 간격이 너무 벌어져 경로 구실을
못 한다. 되살리려면 이 판단부터 뒤집어야 한다.
(회귀 테스트 `shardCharactersCannotBeFinishedByAttendanceAloneOnPurpose`가 이 사실을 고정한다.)

### ⚠️ 7·28일차를 반복 회차와 섞지 말 것

정책 구현은 *"7의 배수이면서 **캐릭터가 걸리지 않은** 회차"* 를 반복 번들로 삼는다.
예전 구현처럼 `contentTier = if (tier > 7) 7 else tier`로 접으면, 7일차가 캐릭터뿐이므로
**14일차에 이미 가진 캐릭터만 나오고 소모품이 통째로 사라진다.**

## 3. 보유 상한

| 종류 | 상한 |
| --- | --- |
| 형세 보기 1회권 | 99 |
| 추천 수 1회권 | 99 |
| **광고 스킵권** | **9** |

상한의 목적은 재고 관리가 아니라 **행동 유도**다 — 쌓이면 가치가 희석되고 "모으는 재미"에
빠지므로, *"어차피 또 받을 것이니 쓰자"* 쪽으로 민다. 1장의 자동 수령 정책과 짝을 이룬다.

**광고 스킵권만 낮은 이유**: 이건 **광고를 안 보게 해 주는** 표다. 넉넉히 쌓이면 광고 수익과
프리미엄 구독의 의미가 함께 옅어진다.

⚠️ **상한 초과분은 버려진다.** 표대로면 4일차 3 + 14일차 3 + 21일차 3 = **정확히 9**라,
**35일차부터 매 반복마다** 스킵권이 상한에 걸린다. 이건 의도된 갈증이지만, **화면은 그 사실을
감추면 안 된다** — 청구 상세가 실제로 0개 들어오는 항목에 "보유 상한"을 표시한다.
