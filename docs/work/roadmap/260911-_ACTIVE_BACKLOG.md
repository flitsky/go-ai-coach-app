45. **⚠️ 스크롤 부모 안에서 `min(가로, 세로)`로 크기를 정하면 늘 가로폭이다 — 넓은 화면에서만 넘친다** (2026-09-11, #139)
    - `GoBoard`는 `boardSide = min(maxWidth, maxHeight)`로 정사각형을 잡는데, 대국 화면이 `verticalScroll` 안이라
      `maxHeight`가 **무한**이다. 그래서 판은 언제나 가로폭을 쓴다. 세로로 긴 폰에서는 멀쩡해 보여 **아무 신호가 없었고**,
      폴드 안쪽 화면(≈690×829dp)에서 판이 세로 ~680dp가 되어 조작부 전부를 화면 밖으로 밀어낸 뒤에야 제보로 드러났다.
    - ⚠️ **넓은 화면은 에뮬레이터 하나로 흉내 낼 수 있다**: `adb shell wm size 1812x2176`(폴드 안쪽) · `904x2316`(커버).
      끝나면 **반드시 `wm size reset`** — 잊으면 이후 테스트가 전부 다른 화면에서 돈다.
    - ⚠️ 판을 화면에 맞추려거든 **스크롤 바깥에서 잰 높이**(뷰포트)를 넘겨야 한다 — 스크롤 안에서는 잴 높이가 없다.

    - **그래서 결제는 미루고 5단계를 출석 보상으로 돌린다(2026-08-29 사용자 결정)** — 별도 항목으로 발행. 이 항목의 **특전·결제 배선 코드는 지우지 않고 그대로 둔다**: 카탈로그에 `BotUnlockSource.Purchase` 캐릭터가 없어지면 `isBotCharacterPerkActive`가 항상 `false`라 조용히 잠들 뿐이고, 유료 상품을 다시 열 때 그대로 깨어난다.
    - 남은 것(콘솔이 열린 뒤): ⓐ 4,900원 상품 등록 + 라이선스 테스터, ⓑ 상품 ID를 `local.properties`의 `billing.botCharacterProductId`에 기입, ⓒ `isBotCharacterPurchaseEnabled`를 `true`로, **ⓓ 획득 모델을 두 축으로 가르고(무료 경로 × 구매) 위 ⓑ·ⓒ를 함께 처리할 것** — 이게 빠지면 ⓐ~ⓒ를 다 해도 아무 일도 안 일어난다.
