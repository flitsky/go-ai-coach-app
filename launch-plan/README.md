작성일: 2026-08-13

본 문서는 `feature-access-principles/README.md`의 원칙 위에서, **Google Play 초도 버전 발행**을 위한 구체적인 기능별 정책과 실행 체크리스트를 담습니다. `premium-mode/README.md`·`auth-onboarding/README.md`와 동일한 방식으로 계속 갱신되는 히스토리 문서이며, 작성 과정에서 자연스럽게 **근시일 로드맵 문서** 역할도 겸하게 될 예정입니다(작성자 본인 언급, 2026-08-13).

### 지금의 임계 경로는 하나다 — 비공개 테스트 14일 카운트다운

2026-08-30에 사용자가 확인한 바(콘솔 화면 직접 확인): "수익 창출" 탭의 잠금을 따라가면
**앱 콘텐츠 패널이 아니라 프로덕션 액세스 체크리스트**가 나오고, 거기서 막고 있는 것은
*"12명 이상의 테스터를 대상으로 14일 이상 비공개 테스트 실행"* 한 줄이며 그때 **11일차**였다.
12명 참여 확정이 2026-08-19이므로 **2026-08-31 기준 12일차, 완료 예정 ~2026-09-02.**

- ⚠️ **설정할 것이 없는 순수 시간 게이트다.** 기다리는 동안 아래 A의 나머지를 처리하면
  임계 경로가 겹치지 않는다.
- ⚠️ **도중에 참여자가 12명 밑으로 떨어지면 카운터가 리셋될 수 있다**(미확인이지만 실재 위험으로 다룰 것).
- ⚠️ **IARC·데이터 보안·개인정보처리방침 필드가 *추가로* 막고 있는지는 확인되지 않았다.** 그 화면은
  프로덕션 액세스 체크리스트만 보여줬다 — **거기 안 나왔다고 셋이 해결된 것으로 넘겨짚지 말 것.**

### 260817 오후 갱신 — 이번 세션에서 실제로 처리한 것
사용자가 제안한 순서(①런처 아이콘+스토어 아이콘/피처그래픽 ②개인정보처리방침 노출 ③요금 안내 문단+스크린샷) 그대로 진행:
1. 런처 아이콘 배선 + adaptive icon(foreground/background/monochrome) 생성, 에뮬레이터 실기 검증.
2. 스토어 고해상도 아이콘/피처 그래픽은 이미 존재했음을 재확인, `design-handoff/`로 정본 커밋.
3. 개인정보처리방침 URL 실제 접속 확인 후 설정 화면에 링크 추가(4개 언어), 에뮬레이터에서 탭→브라우저 오픈까지 검증.
4. `store_listing.txt` 요금 안내 문단 정정(순수 1시간 타이머 + 무르기 클레임 프로모션 반영).
5. 스크린샷 4장 재캡처 필요 여부를 실기로 직접 비교해 판단(필요했음을 확인) 후 재캡처, `design-handoff/export/2026-08-17-v0.1.11/`로 신규 폴더 커밋.
6. 부수적으로 발견한 이슈(형세 보기 오버레이 미표시)는 범위 밖으로 판단해 별도 백그라운드 조사로 분리. **→ 2026-08-29에 해소 확인, 아래 260829 갱신 2번 참고.**

남은 건 전부 Play Console 콘솔 작업(개인정보처리방침 필드 등록, IARC 설문, 데이터 보안 양식)과 기획 디자이너 회신 대기 여부 결정뿐 — 코드/자산 쪽에서 이 세션 범위 안의 갭은 소진됨.

### 260829 갱신 — 스토어 자산 재정렬, 그리고 targetSdk 경고의 진짜 원인

**1. 스크린샷/등록정보가 다시 stale해져 있었다.** 위 "260817 해소됨" 두 항목은 그 시점에는 맞았지만
그 뒤로 참여/리텐션 기능이 대거 들어오면서 다시 어긋났다 — 이 문서가 v0.1.11 자산을 가리키는 동안
코드는 **v0.8.2**까지 갔다. 실제 차이: 난이도 드롭다운이 **상대 캐릭터 픽커로 통째 대체**(초보~초고수
5단계), 홈 화면에 **대국 기록** 카드 추가, 대국 화면에 **1회권 재고 바**+사용 버튼 추가, **출석 보상**
도입. 스크린샷 5장(신규 `05_character_picker` 포함) 재캡처와 `store_listing.txt` 갱신을 마쳤다 —
`design-handoff/export/2026-08-29-v0.8.2/`가 정본, 업로드용 사본은 `dist/play-store-assets/`.
**업로드 자체는 콘솔 작업이라 사용자 몫이다.**

**2. 2026-08-17에 열어 뒀던 "형세 보기 오버레이 미표시"는 해소됐다 — ⚠️ 목록에서 삭제했다**
(사용자 확인, 2026-08-29). 원 보고의 증상 두 가지가 실기 재캡처에서 모두 사라진 것을 확인했다:
보드 위 영역 음영 오버레이가 형세 보기 ON과 함께 정상 렌더되고(`screenshots/03_eval_coaching.png`),
"고정값"이라고 적혀 있던 형세/승률 표시도 착수마다 갱신된다(B +53.0 → +49.3 → +42.2 → +10.2).
`ui/GoBoard.kt`의 렌더 조건에도 원 보고가 지목했던 `premium.isActive` 게이트가 남아 있지 않다.
언제 어느 커밋에서 고쳐졌는지는 특정하지 못했다 — 참여/리텐션 트랙에서 1회권 경로를 붙이며
게이트를 손본 것으로 보이나, 증상이 사라진 것이 확인된 이상 더 파지 않는다.

**3. "앱 버전이 낮다"는 Play Console 경고는 코드 문제가 아니다.** `targetSdk`는 이미 **36**이다
(`a4f33ab`, 2026-08-12) — `app-android/build.gradle.kts`와 release 머지 매니페스트
(`targetSdkVersion="36"`) 양쪽에서 확인했다. 경고가 가리키는 것은 **콘솔에 게시된 번들**이다:
내부 테스트 트랙에 올라가 있는 AAB는 버전 2(0.1.1, 2026-08-06)로 **targetSdk 상향보다 엿새 앞선다.**
따라서 해소 방법은 SDK를 올리는 것이 아니라 **현재 소스로 AAB를 새로 빌드해 올리는 것**이다.

**빌드 완료(2026-08-30 최종)**: 하루에 빌드가 다섯 번 갈렸다 — 803은 홈·대국 화면 변경
(#34~#38), 804는 1회권 결함과 홈/캐릭터 문구(#43~#46), 805는 캐릭터 이름 다국어화(#32),
806은 학습 강좌 소개 다국어화(#33)로 각각 대체됐다.
**업로드 대상은 아래 807 하나이며, 803~806은 콘솔에 올라간 적이 없다.**

⚠️ **AAB는 코드가 멎은 뒤에 만든다.** 805는 #32보다 28분 먼저 빌드돼 그 수정이 **빠진 채**
"업로드 대상"으로 표기돼 있었다 — 번들의 dex를 열어 새 문자열이 없는 것을 확인하고서야 알았다.
**낡은 산출물에 "이걸 올리세요" 딱지가 붙어 있는 것이 위험의 본체다.** 그래서 807은 두 수정이
실제로 들어갔는지(`Tengen the Master`, `Baduk Edu`) dex에서 직접 확인했다.

스크린샷은 805 시점 그대로 쓴다 — #32·#33은 **한국어 화면을 바꾸지 않고**(캐릭터 이름은
한국어가 그대로, 강좌 소개의 `· 한국어` 표기는 비한국어에만 붙는다) 세트가 한국어이며,
학습 화면은 애초에 다섯 컷에 없다.

| 항목 | 값 |
| --- | --- |
| 산출물 | `dist/go-ai-coach-play-internal.aab` (111MB, gitignored) |
| sha256 | `47340a959ae17b607612db2d9f7c548b63cc4bd18a103374d5e8132e97e7725d` |
| versionCode / versionName | **807 / 0.8.7** (`bump-version`이 매 빌드마다 자동 증가) |
| targetSdk / minSdk | **36 / 26** |
| 빌드 명령 | `make play-internal-aab TARGET=emu` — ⚠️ 기기가 둘 연결돼 있으면 `doctor`가 막는다 |

수치는 추정이 아니라 **번들 안의 매니페스트를 직접 열어** 확인한 것이다(`versionName=0.8.7`) —
게시 번들이 0.1.1이던 것이 경고의 원인이었으므로, 소스가 아니라 산출물에서 확인하는 것이 이

다섯 장은 `v260830.1754` 기준이며 807에서도 같은 화면이라 그대로 쓴다.

## 2. 기능별 초도 정책

| 기능 | 초도 정책 | 향후 계획 |
| --- | --- | --- |
| 기권 / 통과 | 상시 무료 | 변경 없음 |

**현재 코드 상태 (2026-08-14 갱신)**: 위 표의 "초기 유저 한정 무료 활성화 프로모션"은 커밋 `5fc7b49`(2026-08-13)로 **구현 완료**됐습니다 — `ui/GamePlaySection.kt`의 클레임 다이얼로그(무르기 버튼 탭 시 노출)와 `PremiumState.isUndoClaimed`(로컬 그랜드파더링 플래그)가 실제로 존재하며, 무르기는 더 이상 "게이팅 없는 상시 무료"가 아니라 "클레임했거나 프리미엄이면 사용 가능"으로 좁혀진 상태입니다. 이 절이 한동안 "아직 구현되지 않은 목표 상태"라고 적어뒀던 것 자체가 구현 완료 후 갱신되지 않아 실제 코드와 어긋나 있었습니다 — 아래 5장도 함께 정정했습니다.

## 3. "무르기" 초기 프로모션 — 그랜드파더링(선점 혜택 유지) 메커니즘

**목적**: 초도 발행 시점에 무르기를 무료로 체험/획득한 유저는, 이후 버전에서 무르기의 기본 정책이 광고/유료로 바뀌더라도 계속 무료로 쓸 수 있어야 한다. "먼저 써본 사람 손해 안 보게" 하는 선점 혜택입니다.

**핵심 설계 원칙 — 정책이 아니라 클레임 사실을 저장한다**:
게이팅 로직을 "지금 무르기가 기본으로 무료인가?"로 판정하면 안 됩니다. 미래에 기본값이 바뀌는 순간 과거 유저까지 같이 잠기기 때문입니다. 대신 **"이 유저가 무료 클레임을 받은 적이 있는가"라는 사실 자체를 로컬에 한 번 기록**하고, 게이팅은 그 기록을 OR 조건으로 확인해야 합니다.

```
로컬 저장: claimedFeatures = {"undo"}   // 클레임 시점에 1회 기록, 이후 절대 재평가 안 함

isUndoUnlocked =
    claimedFeatures.contains("undo")   // 그랜드파더링 — 정책이 바뀌어도 항상 true
    || premium.isActive                // 일반 프리미엄(영구구매/광고 1시간)
```

즉 "무르기가 오늘 기본으로 무료냐"를 다시 묻는 게 아니라 "이 사람이 예전에 무료 클레임을 받았느냐"만 확인하는 구조가 핵심입니다. 이건 지난번 검토에서 제안했던 "기능 활성화 원장(ledger)" 개념의 실제 사례이기도 합니다 — `claimedFeatures`가 그 원장의 한 항목이 되는 것.

**재설치 시 초기화 캐비앗**: `feature-access-principles/README.md` 6장 원칙("앱 내 활동/프로모션으로 얻은 기능 = 기기 로컬 저장, 재설치 시 초기화 고지")이 여기도 그대로 적용됩니다. 새 예외를 만들지 않습니다 — 그랜드파더링도 결국 로컬 저장이라, 재설치하면 클레임 기록도 함께 사라집니다. 클레임 팝업 문구에 "이 기기/앱 설치에 저장됩니다"를 명시하는 걸 권장합니다.
