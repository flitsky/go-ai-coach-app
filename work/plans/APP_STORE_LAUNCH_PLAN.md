## 1. 절차 (처음 한 번)

### 1-1. 사용자 몫 — 계정과 콘솔

1. Apple Developer Program(개인 · U-85) → Xcode › Settings › Accounts에 Apple 계정 → 두 타깃(GoCoach · AssetDownloader)의 Signing에 팀 지정(자동 서명이 앱 그룹 `group.com.zenit9hub.ai.baduk`을 등록한다).
2. App Store Connect: 앱 레코드(이름 「포켓 바둑 코치」 · 기본 언어 한국어 · 번들 ID · SKU `pocket-baduk-coach-ios`) · **Paid Applications Agreement**(세금 · 은행) · Business › Compliance › **Korean Law** 신원 정보(EU를 넣으면 DSA trader 신고).
3. 구독: 그룹 「Premium」 → 상품 `premium_basic_monthly`(1개월 · ₩3,900 — Apple 가격 포인트 확인) · 표시 이름 · 설명(등재 글 문서) · 심사용 스크린샷. 가족 공유 끔 · 도입 혜택 없음(답안지 ⑦ 제안).
4. AdMob: iOS 앱 + 보상형 전면 · 배너 단위 → 세 ID를 `app-ios/Config/Ads.local.xcconfig`에(형식은 `Ads-Release.xcconfig` 머리말 — 커밋하지 않는다). Privacy & messaging에서 유럽 규정 메시지를 iOS 앱에도 게시.
5. 모델 팩: `make ios-package-model-pack`(정식 판 Xcode로) → Transporter로 `app-ios/build/asset-packs/katago-models.aar` 올리기 → 처리 완료 메일.

### 1-2. 빌드와 TestFlight

1. 맥 준비(처음 한 번): `make ios-prebuild-engine-device` · `make prepare-friend-assets`(KataGo 설정 둘) · ffmpeg(배경음악) · JDK 17.
2. (선택) `make ios-run-release` — Release 구성을 시뮬레이터에서 1분.
3. Xcode › GoCoach 스킴 · Any iOS Device › Product › **Archive** → Organizer › **Generate Privacy Report**(답안지 ①과 대조) → Distribute App › **App Store Connect**.
   - 시험 광고 ID로 archive하면 `scripts/ios-bundle-resources.sh`가 멈춘다(실제 ID가 `Ads.local.xcconfig`에 있어야 한다).
4. TestFlight 내부 그룹(본인)에 넣고 아이폰 TestFlight 앱으로 설치 → **§2 시험표**를 돈다 → 실패는 `#299`부터 새 번호.
5. 고친 빌드를 다시 올릴 때 빌드 번호를 어떻게 올릴지는 시험표의 열린 물음 2.

### 1-3. 제출

1. 방침 · 지원 페이지 iOS 판 배포(답안지 ⑧) — **제출보다 먼저.**
2. 등재 글(4개 언어) · 스크린샷 · 카테고리 · 저작권 · 지원 URL(등재 글 문서 1 · 7절).
3. App Privacy · 연령 등급 · 콘텐츠 권한 · 수출 규정 확인 · 심사 메모 · 가격과 배포 국가 · Mac/Vision Pro 끄기(답안지 ① ~ ⑦).
4. 버전 페이지에 빌드 선택 → 구독 상품과 모델 팩을 **같은 제출에** 넣는다(Add for Review) → **출시 방식: 수동**.
5. 반려되면 사유와 대응을 #298 카드에.

### 1-4. 승인 뒤 (손으로 출시)

1. 방침 · 지원 페이지가 배포본인지 다시 본다 → App Store Connect에서 **「이 버전 출시」**.
2. AdMob 「앱 연결」(App Store 등록 뒤에만 된다) · app-ads.txt가 있는 개발자 사이트 확인.
3. rezen.dev 제품 페이지에 App Store 링크 · 마케팅 URL 채우기.
4. 태그 · 릴리스 기록 — iOS 태그 이름은 그때 정한다(안드로이드 `v1.8.4`는 이미 있다).

#### 0-3. 올리기와 설치

0. (선택) `make ios-run-release`로 Release 구성을 시뮬레이터에서 먼저 1분 본다. 개발자 2차 메뉴가 없는지 같은 것을 TestFlight 전에 걸러 낸다. 구독과 실제 광고는 여기서 볼 수 없다(Makefile 주석).
1. Xcode에서 GoCoach 스킴을 고르고 대상을 Any iOS Device(arm64)로 둔다. Product › Archive를 누른다(Release 구성).
2. Organizer › Distribute App › **App Store Connect**를 고른다. 「TestFlight Internal Only」로 올린 빌드는 내부 그룹에만 넣을 수 있다(https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview). 통과한 빌드를 #298에 그대로 쓰려고 App Store Connect로 올린다.
3. App Store Connect › TestFlight에서 처리가 끝나면 빌드를 내부 그룹(본인)에 넣는다. 수출 규정 질문은 나오지 않아야 한다(`INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO`, `project.pbxproj`). 「Missing Compliance」가 뜨면 적어 둔다.
4. 아이폰의 TestFlight 앱에서 설치한다. **1.8.4 (10804)**인지 확인한다.
5. TestFlight 빌드는 90일 뒤 만료된다.

#### 0-6. 주의

1. **실제 광고.** TestFlight 빌드는 실제 광고 ID로만 만들어진다(0-1 표). 보상형 광고와 다시보기 배너 모두 광고 안의 단추나 링크는 누르지 않는다. 보상형은 끝까지 본 뒤 닫기만 누른다. 개발 중 실제 광고 단위에 노출과 클릭이 쌓이면 AdMob이 계정을 제한할 수 있다(`app-ios/Config/Ads.xcconfig` 주석). 이 표 전체에서 실제 보상형 광고는 **4편**(A9 1편, B4 2편, B21 1편)이고, A9 ⑤를 하면 1편이 더해진다. 다시보기를 열 때마다 배너 노출도 쌓인다. 이 기기를 AdMob 시험 기기로 둘지는 결정이 필요하다(맨 아래 「열린 물음」 1).
2. **데이터를 지우는 시험은 맨 끝에 한다.** 대상은 A14와 B6 · C1 · C11 · C14의 재설치, A13 · C8의 개발자 모드 끄기다. 출석, 캐릭터, 1회권, 대국 기록, 설정이 모두 사라진다.
3. **개발자 모드는 A13 · C8을 할 때만 켠다.** 켜 둔 채 3시간 구간이 바뀌면 다음 실행에서 모든 기록이 지워진다(`IosAppStartup.kt`).
4. **샌드박스 갱신 속도를 바꾸는 시험(A10 경로 2)은 Media & Purchases에서 로그아웃해야 한다.** 그 상태에서는 TestFlight 팩을 받지 못할 수 있다(0-2 ⑦). 모델 받기와 재설치 시험을 먼저 끝내고, 끝나면 다시 로그인한다.
5. 실패 기준이 「충돌」이나 「데이터 손실」이면 그 시나리오가 C 표에 있어도 A로 올려 다룬다.
6. **하루는 UTC로 바뀐다 — 한국 시간 오전 9시.** 출석(`shared/.../application/attendance/AttendanceCheckIn.kt` utcDayIndex)과 오늘의 운세가 그렇다. 1일 1회 뽑기는 뽑은 때부터 24시간이다. 「2일차」 시험은 다음 날 오전 9시 뒤에 한다.
7. **무료 사용자는 「문하생 판다」 하나만 가진다.** 수제자 반상은 출석 7일차, 관장 천원은 출석 28일차, 돌뫼 · 꼬북은 광고 조각이다(`shared/.../application/botcharacter/BotCharacterCatalog.kt`). 광고 1시간은 캐릭터를 열지 않는다. 다른 캐릭터로 두는 시험(A4 · D)은 구독(A8) 뒤에 한다.

1. **실제 광고만 나오는 TestFlight 빌드:** archive 검사 때문에 TestFlight 빌드에는 실제 광고 ID만 들어간다. 코드에 시험 기기 설정(testDeviceIdentifiers)이 없다. 고를 길은 둘이다.

2. **고친 빌드를 다시 올릴 때의 빌드 번호:** 한 번 올린 빌드 번호로는 다시 올릴 수 없는 것으로 알려져 있다(이 스레드가 공식 문서로 확인하지는 않았다 — 첫 재업로드 때 확인). iOS 빌드 번호는 안드로이드와 같은 번호를 쓴다(1.8.4 / 10804, `bump-version.sh`가 함께 올린다). 다시 올릴 때 번호를 어떻게 올릴지 정해야 한다(U-87 후보).
