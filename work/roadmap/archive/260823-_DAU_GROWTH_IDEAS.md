# 일일 접속량(DAU) 증대 아이디어 모음

작성일: 2026-08-23

본 문서는 **go-ai-coach** 앱의 일일 접속량(재방문)을 늘리기 위한 아이디어를 모으고 논의하는 **초안/브레인스토밍 문서**입니다. 확정된 기획서가 아니라, 아이디어를 계속 추가하고 상태(제안/논의중/채택/보류/기각)를 갱신해가며 함께 다듬어 나가는 것을 전제로 합니다. chess.com처럼 "매일 다시 찾아오게 만드는" 장치가 이미 검증된 서비스의 기능을 참고 사례로 정리하고(3장), 그걸 우리 앱 조건에 맞게 변형한 아이디어를 추적 가능한 목록으로 관리합니다(4장).

---

## 1. 문제 정의

### 1.1 배경

`GOOGLE_PLAY_LAUNCH_PLAN.md` 0절 기준으로 리팩토링 축은 종료되고 초도 발행 단계에 들어섰습니다. 발행 이후 다음 과제는 "만든 기능을 계속 쓰게 만드는 것" — 즉 일일 접속/재방문입니다. 이 문서는 그 다음 단계를 준비하는 사전 브레인스토밍입니다.

### 1.2 "일일 접속량"의 정의 — 열린 질문

"일일 접속량을 늘린다"를 실행 가능한 목표로 바꾸려면 먼저 무엇을 잴지부터 합의가 필요합니다. 후보:

- DAU(일일 순 사용자 수) 자체
- 사용자당 일일 세션 수
- 연속 접속일(스트릭) 분포
- D1/D7/D30 리텐션율

현재 앱에는 이를 측정할 analytics 인프라가 없습니다 — `firebase-analytics`는 실사용처가 없어 의도적으로 제외된 상태입니다(`app-android/build.gradle.kts` 주석: "logEvent() 등 실제 사용처가 코드에 전혀 없어"). `DIAGNOSTIC_EVENT_SCHEMA.md`의 런타임 이벤트 로그는 기기별 진단용이지 집계용 analytics가 아닙니다. **아이디어를 도입하기 전에 "효과를 어떻게 잴지"부터 정하지 않으면, 나중에 이 기능들이 실제로 접속량을 늘렸는지 검증할 방법이 없습니다.** (열린 질문 — 7장)

## 3. Chess.com 참고 사례

Chess.com은 "2억 5천만 명 이상"이 쓴다고 소개하는 서비스로(사이트 자체 소개 문구, 2026-08-23 확인), 재방문을 유도하는 장치가 세밀합니다. 사이트 실제 확인 + 공개적으로 널리 알려진 기능을 기준으로 정리했습니다.

| Chess.com 기능 | 무엇을 하는가 | 왜 재방문을 유도하는가 |
| --- | --- | --- |
| Daily Puzzle | 매일 바뀌는 문제 1개 + 연속 해결일 스트릭 표시 | "오늘 것"이라는 한정성 + 스트릭을 깨고 싶지 않은 손실 회피 심리 |
| Puzzle Rush / Puzzle Battle | 제한시간 내 연속으로 문제를 풀며 점수 경쟁 | 짧고 몰입감 있는 세션 — 자투리 시간에도 열게 됨 |
| Play vs Bots | 실력·성격이 다른 봇 캐릭터와 대국(이름·아바타 부여) | 캐릭터에 정서적으로 이입 — "이번엔 이겨보고 싶다" |
| Game Review | 대국 직후 AI가 자동으로 분석 요약(리포트 카드)을 생성 | 대국이 끝나도 "내가 오늘 어떻게 뒀는지" 보러 다시 열게 됨 |
| Lessons / Drills | 진도가 추적되는 일일 학습 코스 | 대국과 별개로 "학습 진도"라는 복귀 이유가 하나 더 생김 |
| Daily(Correspondence) Chess | 하루 1수씩 여러 판을 동시 진행 | 결과를 매일 확인하러 오는 습관 형성 |
| Achievements / Trophies | 마일스톤 달성 시 배지 수여 | 수집 욕구 + 진행 상황의 가시화 |
| 클럽 / 친구 대항전 / 리더보드 | 그룹·순위 기반 경쟁 | 사회적 비교와 소속감 — 가장 강력하지만 계정+서버가 필수 |
| Titled Tuesday 등 정기 라이브 이벤트 | 매주 고정 시간에 열리는 이벤트 | "지금 아니면 못 본다"는 시의성 |
| 알림("당신 차례입니다", 스트릭 경고) | 이탈 직전 사용자에게 푸시·이메일 발송 | 잊고 있던 사용자를 다시 불러옴 |

## 5. 데일리 보상 설계 — 열린 질문 (사용자가 예시로 든 아이디어)

사용자가 예로 든 "매일 접속 시 데일리 보상"은 구체화가 더 필요합니다.

- **보상의 실체**: 앱에 화폐/재화 시스템이 아직 없습니다. 후보 3가지:
  1. 코스메틱(바둑돌·보드 스킨) — 구현 비용은 있지만 `PREMIUM_MODE.md`의 수익화 흐름과 자연스럽게 연결 가능
  2. 일시 기능 해금 — 이미 있는 "광고 시청 → 1시간 기능 활성화" 패턴(`PREMIUM_MODE.md`) 재사용
  3. 순수 진행 표시(재화 없이 스트릭 숫자 자체가 보상) — 구현이 가장 쉽고, 실제로 chess.com Daily Puzzle도 재화 보상보다는 "매일 콘텐츠가 바뀐다 + 스트릭이 쌓인다"는 방식에 더 가깝습니다.
- **스트릭 소실 시나리오**: 로그인 없는 게스트가 재설치·기기 변경으로 스트릭을 잃는 경우, `FEATURE_ACCESS_PRINCIPLES.md` 6장의 "로컬 저장 + 재설치 시 초기화 고지" 원칙을 그대로 적용할 수 있습니다.
- **보상 인플레이션**: 매일 받다 보면 무뎌지는 문제. "보상"보다 "콘텐츠(문제)가 매일 바뀐다"는 축을 우선 검토해볼 가치가 있어 보입니다 — 다만 이건 더 논의가 필요한 지점입니다.
