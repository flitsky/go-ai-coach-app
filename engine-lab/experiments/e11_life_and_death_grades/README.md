# E11 — 사활 문제의 난이도와 생사를 엔진으로 다시 본다 (백로그 #277)

## 질문

「중·고급 사활」의 문제를 맥에서 만들 때(사용자 2026-10-21 — *"엔진이 흑백 모두 최선으로 두어 잡는가 못 잡는가로 보고"*),

1. 만든 문제가 **얼마나 어려운가** — 기본 사활(이미 실은 26문제)보다 확실히 어려운가, 중급과 고급을 무엇으로 가르나.
2. 앱의 풀이기가 내린 생사 판정을 **엔진도 같게 보는가** — 풀이기는 문제 구역 안만 읽는다. 판 전체를 보는 엔진이 다르게 보면 사람이 다시 본다.

## 방법

- 문제와 정답은 **앱이 정한다.** `LifeAndDeathCandidateExportTest`(app-android 테스트, `-PexportLifeAndDeathCandidates`)가 9줄 판 귀 · 변에 궁도를 그리고
  끊긴 데 없는 벽으로 두른 뒤 흔들어 후보를 만들고, 앱의 풀이기(`LifeAndDeathSolver` — 흑백 모두 끝까지 읽는다, 증명)가 실은 문제와 같은 잣대를
  모두 지나는 것만 남긴다. 실은 문제(「기본 사활」)도 함께 내보내 기준선으로 쓴다.
- **난이도 — 사람 모델**(`b18c384nbt-humanv0`): 프로필 `rank_15k` · `rank_10k` · `rank_5k` · `rank_1k` · `rank_3d`마다 처음 국면의 사람 정책을 한 번 평가하고
  (`kata-raw-human-nn 0`), **문제 구역의 빈 점으로만 다시 나눠** 정답 첫 수들에 걸린 확률을 잰다. 9줄 판의 나머지가 비어 있어 정책 일부가 큰 자리로 새므로
  (`outside`에 적는다) 구역 안으로 나눈다. 첫눈의 직관만 잰다 — 수읽기는 안 잰다. 그래서 **기본 사활과의 차이**로 읽는다.
- **생사 — 주 모델**(`kata1-b18c384nbt`, 800방문): 흑이 먼저 둘 때와 흑이 손을 뺐을 때(백이 먼저) 각각, 첫 수를 문제 구역 안으로 묶어(`allowMoves`, 깊이 1) 탐색하고
  목표 무리 돌의 평균 영역 값(흑 기준)을 본다. 흑이 먼저면 +0.5 이상(흑이 목표를 이룸), 백이 먼저면 −0.5 이하(못 이룸)여야 하고,
  셋째로 **흑이 의도한 첫 수를 둔 뒤 백이 판 어디에든 받게 해도**(묶지 않는다) +0.5 이상이어야 「일치」다 — 풀이기는 문제 밖(`,`)에 아무도 두지 않는다고 보는데,
  셋째가 그 가정 없이 판 전체에서 같은 답이 나오는지 되묻는다.

```sh
./gradlew :app-android:testDebugUnitTest --tests '*LifeAndDeathCandidateExportTest*' -PexportLifeAndDeathCandidates
python3 engine-lab/experiments/e11_life_and_death_grades/run.py --label mac-v1
```

## 결론 (2026-10-21, 씨앗 277 — 후보 733 · 기본 26)

실행은 두 단계로 나눴다 — 사람 모델은 싸서 전부(`runs/…-mac-human`), 주 모델 세 탐색은 비싸서 고른 후보만(`runs/…-mac-shortlist`, `--only`).
두 실행 모두 `--candidates`로 넘긴 파일은 생성기 출력(씨앗 277) 그대로다 — 같은 명령으로 다시 만들어진다.

1. **기본 사활은 첫눈에 보인다** — 정답 첫 수의 확률이 모든 프로필에서 가운데 값 0.92~0.97. 맥에서 만든 후보는 가운데 값 0.57~0.64, 아래 사분위 약 0.4,
   아래 10%는 0.1 — 확실히 어렵다. **정답 수순이 길수록 낮다**(`rank_5k`: 3수 0.72 · 5수 0.61 · 7수 0.51 · 9수 0.31).
2. ⚠️ **프로필(급수)이 올라가도 확률이 거의 오르지 않는다** — 사람 모델의 「첫눈」은 사활 문제의 급수를 가르지 못한다. 그래서 중급 · 고급을 「N급용」으로
   이름 붙이지 않고, **기본보다 덜 보이는 것(중급, 세 프로필 평균 0.25~0.6 · 수순 5수 이상)**과 **가장 안 보이는 것(고급, 0.25 미만 · 수순 5수 이상, 또는 9수 이상)**으로만 갈랐다.
3. **생사는 엔진과 같다** — 고른 후보 32개 중 30개가 셋(흑 먼저 · 백 먼저 · 정답 뒤 판 전체) 모두 풀이기와 같은 쪽. 다른 둘(`cand.4821` · `cand.14161`)은
   엔진이 **백이 먼저 둬도 이미 죽었다**고 본다(문제 구역 밖의 사정) — 뺐다. 기본 26개 중 25개가 같고, `ld.eyes.5` 하나는 엔진이 **패가 나는 다른 첫 수**도 좋게 본다 —
   풀이기는 패를 오답으로 친다(사용자 2026-10-21 「조건 없는 생사만」), 고칠 것이 아니다.
4. 엔진의 최선 첫 수가 풀이기의 정답과 다른 문제가 많다(800방문) — 생사가 같으면 받아들였다. 첫 수 하나를 보는 짧은 탐색은 사활 정답의 잣대가 아니다.
