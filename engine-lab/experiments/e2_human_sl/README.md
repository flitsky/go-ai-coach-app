# E2 — 사람 모델(Human SL) 1방문 추출: 손해는 어떤가, 캐릭터 5단계는 어느 프로필쯤인가

**질문**(#215 준비): 사람 모델에서 한 수를 뽑으면(평가 1회) 그 수의 손해는 어떤 분포인가 — 프로필(rank_20k … rank_3d)과 레시피에 따라.
지금 캐릭터 5단계(16방문 + 버킷)와 손해 분포가 비슷한 프로필은 어디인가.

## 방법

- **국면**: E1과 같은 `positions/selfplay-human-v1.json`.
- **사람 정책**: 주 모델 + `-human-model b18c384nbt-humanv0.bin.gz`로 띄운 GTP에서 `kata-set-param humanSLProfile <프로필>` → `kata-raw-human-nn 0`.
  국면의 **전체 수순**을 넘긴다(사람 모델은 직전 수에 반응한다 — 리서치 §3.4).
- **레시피**(`lab/human.py`, KataGo v1.16.4 `chooseIndexWithTemperature`·`interpolateEarly`를 그대로 옮김):
  - **R2 꼬리 누르기** — 확률 1% 미만인 수에만 온도 0.85 → 0.70(반감 80수, 19줄 기준). go-bot(OGS에서 사람과 둬서 보정된 유일한 레시피)의 착수 단계.
  - **R3 전체 온도 1.0** — 사람 정책 그대로(KataGo 문서 권장).
  - 둘 다 통과는 뽑지 않는다(go-bot `humanSLChosenMoveIgnorePass=true`).
- **손해**: E1과 같은 기준 평가(주 모델 800/300방문, `cache/` 공유). 뽑힐 확률 질량의 97%(최대 25수)를 재고, 기대 손해·기준 최선 비율·큰 실수 비율을 낸다.

## 한계

- **세기 보정이 아니다.** 손해 분포가 비슷해도 승률이 같다는 뜻은 아니다 — 사람 모델은 「평소엔 그럴듯하다가 가끔 크게 무너지는」 모양이고,
  버킷 방식은 「매 수 조금씩 어긋나는」 모양일 수 있다. 승률은 대국으로 잰다(E2b — 리서치 §6 M1, 반나절~2일).
- 평가 시간은 맥 Metal 값이다. 폰 시간은 폰에서 잰다(#215 단계 ①).
- 기준 평가가 주 모델이라, 주 모델이 좋아하지 않는 「사람다운 수」는 손해로 잡힌다 — 사람답다는 것과 손해가 적다는 것은 다른 축이다.
