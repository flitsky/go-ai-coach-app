# E1 — 적게·짧게 탐색하면 후보가 몇 개 나오고, 캐릭터는 실제로 무엇을 두나

**질문**(사용자, 2026-10-03): 탐색을 방문 8·16으로, 시간을 1초대로 줄였을 때 ① 그 수의 품질은 어떤가 ② 후보가 여러 개 나오는가.
요지 — 캐릭터는 엔진 분석수 중 **악수를 고르는** 구조인데(최하·중간·최선 버킷), 짧게 탐색하면 **최적수만 나와 실수가 실수가 아니게** 될 우려가 있다.

## 방법

- **국면**: `positions/selfplay-human-v1.json` — 사람 모델(15급·10급·5급)로 둔 대국에서 뽑은 9·13·19줄 국면(초반·중반·끝내기).
- **탐색**: 앱과 같은 GTP 빠른 경로 — `kata-set-param maxVisits N` → `kata-search_analyze`, `numSearchThreads=1`, 후보 최대 8개,
  해석·점수 손해·루트 방문(+1)도 앱 코드 그대로(`lab/gtp.py`). 조건마다 3회, 매번 `clear_cache`(앱의 AI 대 AI와 같다 — 사람 대 AI는 직전 트리를 이어 쓴다).
  - 맥: 방문 4·8·16·32·64(시간 상한 없음 — 맥 Metal은 너무 빨라 시간이 안 걸린다. 같은 방문 = 같은 탐색).
  - 폰(`--adb-serial`): 최대 16방문 + 시간 상한 0.5·1·2·3·5초 — 실제로 몇 방문·몇 후보가 나오는지.
- **캐릭터의 착수**: 앱의 5단계 규칙(`lab/selection.py`)으로, 후보 수 n일 때 각 순위를 둘 **장기 확률**을 정확히 계산(무작위 표본 없음).
- **손해**: 맥 기준 평가 — 주 모델로 국면 800방문 → 기준 최선수, 그다음 대상 수마다 **그 수만 허용해 같은 300방문**으로 점수를 재서
  `최선 점수 − 그 수 점수`(둘 차례 기준, 집). 결과는 `cache/`에 쌓여 E2와 공유한다.

## 실행

```sh
python3 engine-lab/experiments/e1_low_visit_candidates/run.py --label mac-v1
python3 engine-lab/experiments/e1_low_visit_candidates/run.py --label phone-<기기> --adb-serial <시리얼> --sizes 13
```

## 한계

- 맥 결과는 **방문 수** 기준이다. 폰에서 1초에 몇 방문이 나오는지는 폰 모드로 잰다(S22U는 초당 약 6~7방문이었다 — `docs/engine/measurements/`).
- 기준 평가도 엔진이다(300방문). 「손해」는 그 기준 대비 값이지 절대 진실이 아니다 — 1~2집 차이는 잡음일 수 있다.
- 국면은 사람 모델 자가 대국이다. 실제 사용자 대국 국면과 분포가 다를 수 있다.
